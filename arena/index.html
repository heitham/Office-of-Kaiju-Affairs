How this works

The site publishes its own tools

Every page loads one script tag. The tools it registers are generated from the CMS's link graph and content model at publish time — no page hand-codes a tool. That is the whole claim: a thousand-page agency site gets the same agent layer for the same effort as this one.

The slow lane is a real recording

The UI-guessing runs were recorded once, before submission, against this same site with no tools available. Every page load, click, scroll and dead end is in the trace file. Nothing here is simulated for effect.

Where the citizen's facts go

Entering a name and phone number into a form transmits them, whichever way an agent works — our own runs prompted for consent on the permit task in both lanes. The asymmetry is narrower than that, and it is about computing a verdict: check_eligibility takes a person's income, claims history and property as arguments, while reading the same rules off the page takes nothing.

The rules are evaluated inside this page and the site is static, so there is no server to send them to — but your agent cannot verify that and is right not to assume it. Asked to do this task on the ChatGPT surface, an agent put it better than we did: Ordinary browsing required no such transmission because I applied the published rules locally. Observed once, not measured.

The remedy is already in our manifest: the eligibility rules are published as data, so an agent could evaluate them locally and get tool-grade precision at browsing-grade privacy. We did not build that path. It is the design lesson we would act on next.

The human still presses submit

prefill_permit_form fills the form and stops. It has no code path that submits. That is not the agent being polite; it is the tool surface refusing to offer the button.
